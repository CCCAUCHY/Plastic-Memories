# PM 机械测试脚本（v0.26.0）

**前提**：新建会话时选 **PM** 模式；模式名应显示 `PM · 可塑记忆 v0.26.0`。

> 设计原则：
> 1. **两轮完成**：第一轮测工具（含主动隐藏），第二轮测合并后的用户命令（安全区 + 用户稳定化）；
> 2. **证据只认工具输出**：所有复述必须出现在 `run_code` 注释 / `echo` / 工具返回里；
> 3. **禁止推断**：区分「当前可见原文」与「记忆 / retrospect 返回」；
> 4. 标记字符串固定，模型不得改写。

---

# 第一轮：工具（set / 报错 / execute / 主动隐藏 / retrospect）

## 1.1 把下面整段作为一条用户消息发出

    ```
    这是 PM 机制的第一轮自检。严格按步骤执行：不要省略、不要并行、不要提前结束回合。

    1. 用一次 run_code 依次执行三条 bash，输出以下标记（保持原样）：
       echo "PM-A7F3-K9"
       echo "PM-B2D8-Q4"
       echo "PM-C5E1-R7"

    2. 查看上下文里形如 [Plastic-Memories][cookie][N] 的行，找到包围
       PM-B2D8-Q4 所在工具结果的两条相邻 cookie，记作 N1 < N2；
       在下一次 run_code 注释里写下 N1=<数字> N2=<数字>。

    3. 同一次 run_code 里调用 tools.plasticize：
       ops: [{ spans: ["[N1,N2]"], new_text: "⟨PM 第一轮：B 已被隐藏⟩" }], option: "set"
       把返回原文 echo 出来，确认是「已登记 / 预览」。

    4. 下一次 run_code 里调用 tools.plasticize：
       ops: [{ spans: ["999"], new_text: "这个不应该生效" }], option: "execute"
       把错误原文原样 echo 出来。

    5. 下一次 run_code 里调用 tools.plasticize：重新发送第 3 步完全相同的 ops，option: "execute"。
       把返回原文 echo 出来（应包含「逻辑世代 0」「pm-logical-generation=0」）。

    6. 用一次 run_code 执行 bash：echo "PM-HIDE-D-T9"（独立一步，不要调用 plasticize）。

    7. 下一次 run_code 调用 tools.plasticize：
       ops: [{ spans: ["this"], new_text: "" }], option: "execute"
       把返回原文 echo 出来（这是一次**主动隐藏**，应返回逻辑世代 1）。

    8. 下一次 run_code 验证当前上下文（禁止凭记忆）：
       - 在注释里抄下 B 位置的整行（应是 ⟨PM 第一轮：B 已被隐藏⟩）；
       - 抄下第 6/7 步原位置现在的那一行（预期含（主动隐藏）与已塑形）；
       - 用 echo 输出这两行。

    9. 调用 tools.retrospect({ query: "PM-B2D8-Q4", limit: 5 })，
       把返回原文完整放进下一次 run_code 的 echo。

    10. 用不超过 6 行回答：
        (a) 第 5/7 步 execute 返回的逻辑世代号；
        (b) 第 4 步错误原文；
        (c) 第 8 步抄到的两行；
        (d) retrospect 返回的 B 原文首尾各 8 字符。
    所有内容必须能在上面的工具输出里找到。
    ```

# 第二轮：用户命令（合并后的 /plasticize）

第一轮结束后，**不要新建会话**。所有用户操作都走同一个命令：

    /plasticize <区间> <替代文本>
    /plasticize hide <区间>
    /plasticize lock <区间>
    /plasticize unlock <区间>

规则：

- 命令只登记到内存，**发送下一条用户消息时**才约化并落盘；不发消息则丢失；
- 同一轮内多次命令的区间**必须互不重叠**，重叠会拒绝并报错；
- lock 只能选当前未锁定的消息；unlock 只能选当前安全区内的消息；
- 发送消息时：先合并相同操作的连续区间，再写安全区私有记录；若有稳定化/隐藏，再写一条逻辑世代私有记录（逻辑世代 +1）。

## 2.1 依次发送以下命令（每条都应返回「已登记 … 待落盘 N 条」）

    /plasticize lock [N_C1,N_C2]

  - N_C1 / N_C2 = 包围标记 **PM-C5E1-R7** 的两条相邻 cookie 编号（在最新世代里可见）；
  - 应返回「已登记纳入安全区」。

    /plasticize [N_A1,N_A2] ⟨用户稳定化⟩

  - N_A1 / N_A2 = 包围标记 **PM-A7F3-K9** 的两条相邻 cookie 编号；
  - 与上面的 lock 区间不能重叠；
  - 应返回「已登记稳定化/隐藏」。

> 可选语法自检（不影响判定）：
>
>     /plasticize hide [N_H1,N_H2]     → 已登记隐藏
>     /plasticize unlock [N_C1,N_C2]   → 已登记移出安全区
>     /plasticize lock all             → 报错（all 不再是合法区间）
>     /plasticize this                 → 报错（this 语法糖已随合并移除）

## 2.2 再发下面这条用户消息（发送时会先落盘 2.1 的全部操作）

    ```
    这是 PM 第二轮自检。按顺序执行，全部证据写进 run_code 的注释和 echo：

    1. 调用 tools.plasticize：
       ops: [{ spans: ["[N_C1,N_C2]"], new_text: "这个操作应该被拒绝" }], option: "execute"
       把错误原文原样抄进下一次 run_code 的注释和 echo（预期提到安全区 / /plasticize unlock）。

    2. 用一次 run_code 读取**当前上下文**并如实复述（禁止凭记忆）：
       - 抄下 ⟨用户稳定化⟩ 那一行；
       - 抄下第一轮主动隐藏位置的（主动隐藏）行；
       - 回答：PM-C5E1-R7 的原文现在是否仍然可见？（安全区只是禁止改写，不隐藏）

    3. 用不超过 5 行回答：安全区内的标记是否仍可见；用户稳定化是否出现；
       工具命中安全区后世代数是否变化。不得补充工具输出之外的内容。
    ```

## 说明

- `/plasticize` 的替代文本原样读取（可含换行、引号）；空替代文本 = 隐藏（也可用 `hide` 显式表达）；
- 用户命令没有「承载步骤」，所以区间不能用 `this`；
- 安全区完全由日志回放：/plasticize lock/unlock 在发送消息时追加私有记录，之后不再修改；
- 用户稳定化/隐藏会追加逻辑世代私有记录，之后 plasticize 工具结果与 retrospect 的世代号都会把它计入；
- 推理进行中（agent 非 idle）不能执行 /plasticize。
